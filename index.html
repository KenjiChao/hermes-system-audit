已完成的修正

不是只交計畫或隔離副本；下列內容已正式保存，並核對讀回結果。

已套用

文字轉換保留，技術字串不再盲目改寫

Telegram 的 MarkdownV2 格式化路徑，先區分逐字內容與一般敘述，再做 OpenCC 與標點轉換。程式碼、網址、路徑、Markdown 連結目標及明示引文受到保護；新增中文字緊接單引號與全形標點邊界測試。

查看查證依據

獨立審查的 251 項測試與父代理的 354 項整合測試通過。重啟後另經正式 formatter 實際傳送至 Telegram，再從伺服器讀回文字、code entity 與連結目標，確認 prose 轉換而引文／路徑／網址不被改寫。

已退役

移除寬鬆掃描例外與舊同步委派修補

退役 Patch 002 的過寬掃描例外，恢復上游掃描；退役 Patch 003，改由上游依工作階段交付能力處理委派。舊檔已封存，不是不可逆刪除。

查看查證依據

五個既有排程的原始與組裝後提示均通過掃描檢查；四個惡意邊界案例被攔截。這是相容性測試，不是重新執行五個排程。

已保留

SRT 支援及轉換依賴都有持久化

Patch 001 保留 SRT 文件／媒體交付，並把三項回歸測試納入修補。Patch 004 保存文字轉換與測試，OpenCC 1.4.2 已寫入 messaging 依賴及 lockfile，不再靠套用器臨時安裝。

查看查證依據

三項 SRT 回歸測試與依賴檢查通過。實際傳送中文檔名 SRT 後，從 Telegram 下載同一附件並逐位比對，內容完整一致，MIME 為 application/x-subrip。

已安裝

Patch 套用器改成先完整預檢，再受控套用

完整 stack 先在拋棄式環境重播；不使用三方合併或留下 reject 的降級方式。加入安全 journal、回復檢查、協作鎖與檔案權限保留，已套用時不重寫檔案。已同步修改既有 updater 與新建 Patch 的操作提示。

查看查證依據

61 項套用器回歸測試通過，獨立複審另驗八種情境。正式安裝後再次預檢及重複套用，結果為零檔案變更、Git index 不變。

03

排程、設定與服務

整理既有維護流程，沒有新建自動化，也沒有順手更換模型。

已恢復

原 updater 排程恢復，交付目的地明確化

維護期間暫停的既有 updater 已恢復，仍每天 13:00 執行；下一次為 9 月 18 日 13:00（太平洋時間）。報告改由既有維護話題接收，不再是指令說會傳送、實際只存本機的矛盾設定。模型、provider 與其他四個排程保持原樣。

查看查證依據

既有 updater 的一次性只讀交付測試已實際執行。持久執行帳本記錄 completed／delivered，使用新 Gateway worker；沒有執行版本更新或重啟。原 schedule、model、provider 與交付目標未因測試更改。這驗證實際 cron framework 交付，不冒充下一次定時更新已完成。

已清理

移除失效服務、舊重啟腳本與設定殘留

已退役指向不存在暫存腳本的失效服務，移除以日誌安靜或等待超時決定強制重啟的舊工具，保留可還原備份。清掉過時回合上限環境變數；依使用者要求，把新子代理的時間上限設為 3,600 秒。

查看查證依據

正式設定與腳本狀態已核對。時間上限不會延長工具授權等待，也不代表可以重試被拒絕的命令。

保留現狀

沒有批次殺掉瀏覽器或清除歷史資料

背景 browser daemon 不因父程序為 1、執行多日或記憶體加總高，就判定為可刪孤兒；沒有批次終止。聊天資料庫、還原快照、模型預設與其他話題設定未做清理或遷移。

建議做法若後續要回收這些空間或程序，需另做擁有者、活動狀態與資料保留範圍的確認。
